# 多设备音量协同：跨端技术契约

本文件承接[产品要求](../prd/index.md)中已确认的多设备规则，记录各端互操作必须一致的职责边界；它是后续设计目标，不描述现行 BLE 协议已经具备的能力。

少量已配对设备在逻辑上直接组成全连接：每端直接把**自己**的安静需求告知其他端，并在本机独立判断和执行收到的有效需求。不设置固定 Mac 中转、替别的设备转发需求、选主或共识。某个平台在蓝牙链路上担任 central 或 peripheral，只是传输角色，不改变产品中的对等地位。

需求来源是本机录音判断，音量执行是接收端的本机责任，按接收端持有的目标上限处理。接收端必须区分各来源的当前需求，让一个来源的结束不撤销其他来源，并保证重复状态不重复压低。请求在持续录音时续期；接收端短断连期间保留该来源，超过宽限且没有更新才释放。来源全部失效且本轮未被手动接管时，执行端平缓恢复。重连时双方对账当前状态，不重放旧指令，也不根据旧音量结果生成新需求。手动接管属于执行端的整轮状态，不能只在轮末根据当前数值猜测用户意图。身份、会话、版本、认证回执的具体协议和续期、宽限、渐变参数仍待复核，不在这里冒充已经选定的线上格式。

现行实现只支持 Mac 作为 BLE central 向 iPad peripheral 发送认证控制命令，iPad 调整媒体音量后返回认证回执。iPad 持有目标音量设置，Mac 界面可以把用户调整同步给 iPad；`VolumePolicy.target` 在当前音量已低于目标时不调高，目标可为 0。现行命令的 `expiresAt` 仅限制收到命令时能否接受，不是上述持续需求的有效期；续期、宽限和渐变均尚未实现。实现状态与真机证据分别以 [README](../../README.md) 和 [验证记录](../validation.md) 为准。
