# Mac 音频性能分析

2026-10-04 在 macOS 15.4.1、arm64 上检查正在运行的声邻 0.2.0 (5)。目标是解释观察到的音频服务占用，并在保留专用麦克风、持续上下游 Float32 取证和 250 毫秒输入检测周期的前提下减少开销。

## 实机观察与归因

30 秒窗口内，以进程累计 CPU 时间增量除以墙钟时间计算，GUI 平均使用约 4.02% 单核、后台麦克风服务 6.48%、coreaudiod 4.85%、ShenglinDriver 独立宿主 0.60%。这些是优化前某一空闲输入现场的结果，包含系统及其他应用的影响，不能直接当作声邻对音频服务的全部贡献。

GUI 的 8 秒墙钟调用栈采样中，主线程 5,922 次样本有 272 次落在 `InputActivity.poll`，其中 207 次在输入活动属性读取、65 次在 PID 属性读取，主要等待 Core Audio IPC。后台麦克风服务另一次 5 秒采样中，主线程 4,408 次样本有 3,090 次落在 `AudioForensics.status(for:)`，主要等待 `contentsOfDirectory` 和 `getattrlistbulk`。墙钟样本包含阻塞时间，这些比例不是 CPU 占比。

后台服务每秒调用取证状态，旧实现每次列举全部历史文件并读取音频文件修改时间，再同步返回主线程。现场诊断目录有 8,956 个事件分段、304 个音频分段；持续保留的文件越多，状态查询越贵，且会延迟同一主线程的输入轮询。这是本轮最明确的热点。

系统的 coreaudiod 和独立驱动宿主拒绝普通用户的调用栈采样；本机没有可用的免密码 sudo。本轮没有取得这两者的内部调用栈，没有重启音频服务，也没有改变实际取证目录或正在运行的应用。

## 已实施的优化

`AudioForensics` 在现有串行队列上维护每台设备最早保留音频分钟和最新成功写入时间。首次访问、切换目录及现有每 60 秒的容量检查复用一次目录遍历；成功写音频后增量更新，容量淘汰时只统计保留下来的文件。普通状态查询只从缓存计算覆盖时长，停止写音频超过 5 秒仍返回零，写入失败不会制造新的覆盖时间。外部删除文件在下一次容量遍历时刷新，正常后台运行的刷新间隔为 60 秒。持续音频取证与容量上限保持原有行为。

`activeInputDevices` 先读取是否运行输入，只对活动输入进程查询 PID 和设备。空闲进程的 PID 查询故障不再使整个输入状态不可用；活动状态、活动 PID 或设备查询失败仍返回未知状态。没有引入属性监听、进程对象缓存或新的失效生命周期。

## 对照测量

| 测量 | 优化前 | 优化后 | 条件 |
| --- | ---: | ---: | --- |
| 200 轮输入枚举的属性调用数 | 14,400 | 7,400 | 实机 35 个音频进程，活动输入为零 |
| 同一枚举耗时中位数 | 641.5 ms | 509.7 ms | 旧、新交错，各 3 轮；减少约 20.5% |
| 单次取证状态查询 | 79.276 ms | 0.005 ms | 隔离 10,000 个非空分钟音频文件，各 20 次查询；新版为缓存预热后 |
| 新版首次发现已有取证 | — | 210.577 ms | 同一隔离目录的一次初始遍历 |

输入枚举对照未进行音频采集，不包括活动输入的设备读取；其收益来自减少空闲查询。取证测试是大量历史文件下的隔离测量，实际收益取决于文件数量和存储设备。两项结果均不能推导为整机 CPU 按同样比例下降；新版尚未替换正在运行的应用，因此没有部署后的同现场 CPU 对照。

驱动默认 libASPL Syslog tracer 只记录操作、属性、尺寸及状态，不展开 PCM 内容；实时 IO tracing 默认关闭。隔离测试每次属性操作包含 begin/message/end，三轮中位耗时为 Syslog 2.844 µs、纯格式化 1.038 µs。按每秒 100 次属性操作估算，直接调用时间约为 0.028% 单核，未测量 logd 的间接成本。证据不支持为此抑制错误日志；本轮保持驱动和无锁音频缓冲路径不变。

## 验证与证据

`sh scripts/test-input-activity.sh` 编译正式查询函数，替换 Core Audio 属性边界，覆盖空闲查询数与顺序、活动进程设备并集、设备筛选和查询失败。针对旧版的反向验证失败，新版通过。

`sh scripts/test-forensics-retention.sh` 直接编译取证实现，覆盖已有取证发现、切目录、容量淘汰、外部删除后刷新、停止写入超过 5 秒、成功恢复、失败写入及大目录状态查询。稀疏文件仅用于隔离容量测试，不操作真实音频证据。

原始实机采样、CPU 窗口、查询探针与结果、取证基准及构建输出保存在忽略版本控制的 `local/performance-20261004/`。它们属于本地现场证据，不随仓库分发。Mac 无签名 Release 构建、21 项 Swift 测试及既有驱动 C++ 离线测试均通过；构建通过不等于新版已部署或真实通话验证完成。

发布 0.2 beta.2 时，另从干净 HEAD 仅应用本次性能优化及构建号变更，在隔离源码中验证 20 项 Swift 测试和两项性能边界脚本通过。工作区的第 21 项测试属于既有未提交的时钟偏差修正，不包含在这次发布中。隔离发布安装包没有带入该修正及其文档。
