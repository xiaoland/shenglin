# 多设备音量协同：产品要求

本文件记录已确认的产品目标与规则。当前实现和验证范围分别见 [README](../../README.md) 与[验证记录](../validation.md)；这里的完整多设备行为尚未交付。

## 目标与范围

长期方向是具备用户可控空间场景感知、跨平台双向对等能力的音频协同与路由软件。本轮推进按实际输入输出需求协调音量：Mac 本机应用使用输入时保留它自己的输出、降低其他应用，浏览器每个网页单独参与；同一空间内获准参与的设备可向彼此请求安静，由接收端按本机保护与能力执行，包括 Mac→iPad 和 iPad→Mac 的方向。跨设备投放声音和借用麦克风是后续能力，不属于本轮交付。

设备在配对完成时一并确认加入音量协同，此后按空间条件自动参与，无须另设启用步骤。配对信任与空间判断是独立门槛。用户先选择网络条件“同一 Wi-Fi”或“同一局域网”，再选择它与“蓝牙可连接”按“或”或“且”组合。旧设置缺少网络范围时保留 Wi-Fi 范围，不自动扩大为局域网。

“同一 Wi-Fi”以双方通过 Wi-Fi 链路完成新鲜认证往返作为代理；“同一局域网”允许 Wi-Fi 和以太网混合连接。手机走 Wi-Fi、Mac 走网线只满足局域网条件，不满足 Wi-Fi 条件。它们均不证明相同 SSID、接入点或物理同室，也可能受网络隔离影响；两种组合不表示安全等级。配对仍可经局域网完成，不因空间偏好而阻止建立信任。界面允许暂停参与，短暂失去已满足的证据时保留 20 秒宽限；用户主动切换网络范围、组合方式或暂停时立即重算。

## 联动规则

各设备只从**本机录音需求**决定是否向其他设备请求安静。调低本机音量、收到远端请求、声音能量或用户界面状态都不会产生新的录音需求。不同平台取得可靠录音状态的能力须分别验证，不把 Mac 已验证的输入活动观察能力推及 iPad。

多个本机与远端请求合并后，Mac 对允许控制的背景应用施加一次相对增益，不层层相乘；所有本机输入应用的输出保护取并集，即使总请求仍非空，保护变化也应立即重算。输入应用不经过衰减链。系统音量和应用自身音量继续由用户决定。浏览器通过用户逐页调用扩展参加，通话保护与背景调音分开；通话软件静音撤销有效输入需求，用户保护保留，直到明确结束参与或文档实例结束。未接入网页保持原状。

iPad 本机音频会话之间的协调交给系统，声邻不要求控制任意第三方应用的会话。iPad 仍响应远端安静请求，以接收端媒体音量上限执行；本机有录音或录音状态未知时撤销声邻持有的音量改动，保留远端租约。当本机确认空闲且没有手动接管时可继续处理。系统是否 duck 由实际音频会话选项决定，不保证每个录音应用都会降其他应用。

Android 作为同等节点直接与 Mac、iPad 和其他 Android 配对，不依赖特定平台中转。它按本机观察到的录音需求向各对端发送状态，响应远端时采用媒体音量上限，并遵守与 iPad 相同的本机输入保护、未知不续期和整轮手动接管规则。平台无法提供应用身份时，不推断具体应用；传输暂未提供蓝牙证据时，不把局域网互通算作满足严格的双条件模式。

安静请求有有效期，持续需求须续期；来源结束不撤销其他来源，重复状态不反复压低。所有需求结束或到期后解除产品增益；iPad 恢复仍属于声邻持有的旧媒体音量。用户手动调整系统音量或切换输出设备会接管整轮，解除本产品衰减，之后的续期和新请求不能覆盖该调整，所有需求结束后才允许新一轮处理。跨设备输入与回应分离时尊重手动调整，不自动猜测应用关联。任意 peer 控制其他 peers 的实际音量暂列独立候选。
排除应用只决定本机该应用录音是否产生联动需求，不会静音麦克风。由 声邻管理的虚拟麦克风按应用静音另行生效；不能推断其他应用内部是否按下静音。本产品不通过 UI 操作、快捷键、静音播放保活或占用麦克风探针来猜测、维持联动。

局域网代理的误判边界、后台交付及各平台录音状态可行性仍需实测；形成更严格的空间依据时更新本文件。
