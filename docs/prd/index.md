# 多设备音量协同：产品要求

本文件记录已确认的产品目标与规则。当前实现和验证范围分别见 [README](../../README.md) 与[验证记录](../validation.md)；这里的完整多设备行为尚未交付。

## 目标与范围

长期方向是具备用户可控空间场景感知、跨平台双向对等能力的音频协同与路由软件。本轮从现有 Mac→iPad 单向原型推进空间音量协同：同一空间内获准参与的设备，在一端因本机录音需要安静时，让其他参与设备各自降低本机播放音量，包括 Mac→iPad 和 iPad→Mac 的方向。跨设备投放声音和借用麦克风是后续能力，不属于本轮交付。

设备在配对完成时一并确认加入音量协同，此后按空间条件自动参与，无须另设启用步骤。配对取得信任与同空间判断仍是两个独立门槛。用户可选两种平行的空间条件组合：默认满足“蓝牙可连接 **或** 同一 Wi-Fi”即可参与；另一种须同时满足“蓝牙可连接 **且** 同一 Wi-Fi”。本轮将 Wi-Fi 条件操作化为“设备经本地 Wi-Fi 链路发现并与已配对端完成新鲜认证往返”，界面显示这一依据；它是同空间的代理，不证明相同 SSID、接入点或物理同室，也可能受局域网隔离影响。两种组合不表示安全等级。界面允许暂停参与，链路证据短暂消失时沿用请求租约的 20 秒宽限；该时长仍需实测校准。

## 联动规则

各设备只从**本机录音需求**决定是否向其他设备请求安静。调低本机音量、收到远端请求、声音能量或用户界面状态都不会产生新的录音需求。不同平台取得可靠录音状态的能力须分别验证，不把 Mac 已验证的输入活动观察能力推及 iPad。

一台设备同时收到多个有效请求时，只在第一项请求出现时开始一轮音量处理；新的请求和重复状态不应反复降低音量。响应设备按自己持有的目标音量上限处理：当前音量已低于上限时不调高，目标为 0 时可静音。安静请求有有效期，录音持续时须续期；短暂断连时保持已降低的音量，超过宽限仍无更新才释放该来源请求。最后一项有效请求结束或失效，且用户未接管时，才平缓恢复本机音量。用户在本轮手动调整本机音量，就接管**整轮**：该轮之后的新请求不再次降低音量，结束时也不覆盖用户调整；所有请求结束后，新一轮才重新允许自动处理。续期周期、失效宽限及恢复渐变时长仍是待验证的工程参数。

排除应用只决定本机该应用录音是否产生联动需求，不会静音麦克风。由 声邻管理的虚拟麦克风按应用静音另行生效；不能推断其他应用内部是否按下静音。本产品不通过 UI 操作、快捷键、静音播放保活或占用麦克风探针来猜测、维持联动。

Wi-Fi 局域网代理的误判边界、后台交付及各平台录音状态可行性仍需实测；形成更严格的空间依据时更新本文件。
