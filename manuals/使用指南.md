# 使用指南

从[安装与分发](安装与分发.md)了解当前测试版的安装方式。应用显示名是“声邻”，也可在 Spotlight 中搜索。首次打开时允许蓝牙访问；使用 Wi-Fi 协同时，如系统询问局域网访问，也需要允许。从 Dock 或 Spotlight 打开应用会显示主窗口，可直接控制自动协同、背景应用保留音量、设备配对和专用麦克风静音。菜单栏弹窗提供协同与静音的快速开关。主窗口左下角可打开“设置…”或“诊断…”；也可按 ⌘, 打开标准设置窗口。设置集中管理空间条件、登录启动、浏览器扩展、应用排除、麦克风上游与快捷键，登录启动默认关闭。

Android 底部提供“首页”“设备”“设置”三个入口。首页显示自动协同、当前状态与需要处理的事项；“设备”查看已配对设备，点按一台设备查看连接详情或取消配对，从右上角添加新设备；“设置”调整媒体音量上限、Wi-Fi/局域网与蓝牙的组合、名称及权限。详细连接信息和最近一次音量操作放在设置内的“运行详情”，不影响首页操作。

## 配对与应用排除

iPad 主界面显示自动协同、其他设备录音时的媒体音量目标和已配对设备；点按设备可展开连接与空间条件。右上角“设置”中可修改设备名称、选择空间条件或查看运行详情。名称不能留空或超过 32 个字符，配对期间不能修改；Mac 在认证连接后会读取并显示新名称，无需重新配对。

Mac、iPad、Android 和 Windows 可以直接互相配对，不需要固定中转设备。使用新版通用配对时，让两台设备连接可互通的局域网（Wi-Fi 或网线）；在一端显示本机验证码，在另一端选择发现的设备并输入六位码。Mac 入口在“添加设备…”弹窗，iPad 的“添加设备”可以显示验证码或查找设备，Android 在首页开启自动协同后，从“设备”页进入“添加设备”显示配对码或查找对端。验证码两分钟内有效，最多尝试三次。验证通过后仍需完成新密钥的双向连接认证，待激活状态不表示已经可协同；各条配对关系独立保存、独立续期。

iPad 保留“通过蓝牙与 Mac 配对”入口，用于原有蓝牙配对方式；已保存的 Apple 配对关系继续使用原链路。通用局域网配对后的 Android 关系复用配对密钥建立蓝牙状态链路；在设置中先选网络范围“同一 Wi-Fi”或“同一局域网”，再选它与蓝牙按“或”或“且”组合。原设置缺少网络范围时默认 Wi-Fi；Mac 用网线、手机用 Wi-Fi 时，需选择局域网才能由网络条件满足协同。切换范围立即重新判断，不继承旧范围的宽限。Android 的蓝牙需授权并开启；Android 11 及以下进行扫描时还需开启系统定位。Mac↔Mac 目前没有蓝牙证据，因此不满足双条件模式。Android 可通过“取消配对”移除指定关系；Mac 和 iPad 在设备行展开后也可取消单台设备的配对。取消前会确认设备名称，其他已配对关系不受影响，再次加入需重新验证配对码。

Mac 默认让所有活动录音应用参与协同；在设置的“排除应用”列表中勾选应用，或用“添加排除…”选择 `.app`，即可让该应用录音时不影响已配对端。排除项按 bundle ID 保存，应用重启后仍有效。Android 的公开录音观察不提供可靠应用身份，因此不提供按应用排除。

## 音量协同

Mac 主窗口区分“其他设备录音时”和“本机录音时”的背景保留比例（0%～100%），默认均为 25%；保留 100% 表示不降低。例如音乐应用原音量为 40%，保留 25% 后相当于其原来的四分之一，声邻不会改变系统音量。输入应用及已授权的通话网页保持原输出。没有配对设备也可使用本机协同；多个请求重叠取较低增益，不重复相乘。此前整体音量上限与新增益不同，升级时新设置采用默认值，请重新确认比例。

Mac 原生应用调音需要 macOS 14.2 以上及系统音频录制权限。首版仅支持默认输出的无输入流、单流双声道 Float32 路径；耳麦、双工或多流设备等未验证路径保持原音量，主窗口提示无法调低，诊断显示原因。诊断也显示本机输出、受保护应用与网页参与状态。设备行可查看连接与空间条件；“可协同”不等于所有输出已经调低。录音结束时解除本产品增益，用户修改应用自身音量不会被恢复成旧值；本轮手动调整系统音量或更换输出设备会解除本轮衰减，直到所有请求结束。

iPad 继续使用媒体音量上限（0%～50%），当前已低于上限时不调高。iPad 本机录音时的会话协调交给系统；有本机录音或状态未知时，声邻撤销自己持有的媒体音量改动，远端请求仍按租约保留。本机空闲后可继续响应未被手动接管的请求。iPad 的“立即恢复音量”会接管当前需求轮次。输入在一端、回应在另一端时可用手动调整保留回应；不会自动建立跨应用关联。

## 浏览器网页

首版以 Helium/Chromium 和 ChatGPT Voice 为基准。在 Mac 的“设置…”→“浏览器协同”点“设置浏览器扩展…”，然后在浏览器的扩展管理页开启开发者模式，加载显示的 `extension` 文件夹。该扩展是 Mac 的本机适配器，不需要作为新设备配对。首次加载或版本更新后的重载需由用户在浏览器管理页完成。

每个需要参与的网页分别调用“声邻网页协同”：ChatGPT 页选择“通话”，然后再开启 Voice；背景音乐页选择“背景”。已在进行的 Voice 无法补观察既有音轨，应结束后重新开启。通话页没有音频重放，输出保持原路径；背景页音频只在浏览器内重放并施加增益，不传给 Mac。ChatGPT 软件静音会停止该页安静需求，但继续保留对端声音；通话结束后可选“不参与”撤销显式保护。

同站两个标签页分别参与。刷新、跨站导航或关闭后不继承旧参与，须再次调用扩展；同文档页面内导航保留通话保护，背景捕获遇到加载会释放，必要时重新调用。未接入网页保持原状，其浏览器 HAL 活动不代替网页有效输入。扩展、Mac 断线或五秒控制租约过期后自动释放背景捕获，需要再次授权背景页。弹窗只提供“不参与 / 通话 / 背景”角色选择；选中项表示当前角色，右上角圆点表示 Mac 连接状态。仅需操作时显示提示，详细状态可在 Mac 诊断中查看。
## 专用麦克风

专用麦克风需先安装 App 内附带的 HAL 驱动；普通安装不会自动启用它。设置中的“安装驱动…”会安装应用内已签名的驱动，并按 macOS 要求请求管理员认证、重启音频服务。在设置的“专用麦克风”中点“添加应用…”，选择应用及其物理上游输入，仅为需要独立控制输入的应用创建设备，例如 **声邻 · 会议应用**。每台虚拟设备在创建时采用所选上游的采样率与声道数；更换上游时应先结束该设备的录音，若格式变化，设备会重建，目标应用可能需要重新选择输入。然后在该应用的音频设置中选择这个设备；系统默认输入可继续使用物理麦克风。首次使用时允许 声邻访问麦克风；如果拒绝，菜单会显示原因，需在系统的麦克风隐私设置中重新允许。打开 声邻后，系统会注册后台麦克风服务；关闭或退出 GUI 不会中断专用设备的声音，后台进程异常退出时由 macOS 重启。设备按需创建，应用重启和取消静音都不会删除它；停止使用后可点“移除”。其他应用继续使用原有输入，不会自动生成虚拟设备。

## 静音与快捷键

声邻中的静音开关控制整台专用设备，并让仅使用已静音设备的进程停止触发音量协同。每台专用设备还可在设置的专用麦克风中录入一个全局快捷键，用至少两个 ⌃、⌥、⌘ 修饰键配合字母或数字，按 Esc 取消录入；快捷键切换该设备现有的静音状态，仅在关闭“让前台应用也响应同一快捷键”时成功切换后播放系统 `Ping` 提示音，重启后保留，移除设备时清除。组合若无法注册，设置窗口会提示换一个；对已知的 macOS 窗口快捷键，设置窗口会显示冲突警告。默认使用非独占 Carbon 热键：其他全局热键注册者可共享组合，但应用内快捷键可能收不到原始按键。设置窗口可显式开启“让前台应用也响应同一快捷键”：声邻先注销 Carbon 热键，再申请 macOS“输入监控”授权并使用只读事件监听，不阻断前台按键；关闭后销毁监听并恢复 Carbon。此监听由系统交付所有按键按下事件，声邻仅对已配置组合切换静音、忽略自动重复且不记录其他按键。授权未完成时 声邻快捷键暂不可用，可在系统设置授权后点“重新检查授权”。不要让两个需独立控制的应用共用同一台专用设备；其他应用若选了同一设备，也会一起静音。每台设备的静音与样本缓冲独立，排除项仍只控制音量协同。如果物理供源断开、样本过期或后台服务尚未恢复，设备将归零；音频服务重启后的设备默认静音，等待 声邻恢复状态。最多配置 32 台专用设备，未添加应用时不发布输入设备。

## 诊断记录

诊断功能自动把每台专用设备送入 HAL 前的 Float32 音频、HAL 实际返回给客户端的 Float32 音频、事件及每 5 秒的采集和驱动性能计数保存在本机，按时间和进程标识记录。音频与事件按分钟分段，默认总容量上限为 40 GB；仅当诊断目录超过设置的上限时，从最旧证据开始淘汰。诊断窗口可手动标记现场时间；持续取证不依赖标记，标记也不免除容量淘汰。独立的“诊断”窗口显示覆盖时长、丢块和写盘错误，可选择外置存储目录、设置容量上限并导出 ZIP。外置诊断盘断开或目录换盘时会停止写入并显示错误；重新接入后请重新选择取证目录。音频可能包含私人谈话，不会自动上传；分享诊断包前请自行检查内容。上游记录来自 AVAudioEngine 格式转换之后，并非 USB 原始数据。

## 分析诊断包

导出后可用 `python3 scripts/audio-forensics.py <设备目录>/rolling --stream hal-output` 查看各客户端 PID 的帧数与时间戳；指定 `--pid <PID> --wav /tmp/hal.wav` 可提取某客户端的音频。将 `--stream upstream` 用于同目录的上游记录；`rolling/*-events.jsonl` 包含事件和性能快照。两路 hostTime 使用同一 Mach 时钟，换算系数见 `manifest.json`；各自的 sampleTime 属于不同音频时钟，不能直接相减。WAV 按收到的块顺序拼接，不能从拼接后的 WAV 推断真实停顿长度。

## Windows 与远端麦克风

在管理员终端用 `shenglin.exe pair` 显示本机六位码，让另一端发现并输入；也可在 Mac“添加设备…”显示验证码，Windows 执行 `shenglin.exe pair "Mac 显示的设备名" 六位码`。服务继续运行即可完成新密钥的双向认证，`status` 中该 peer 的 `pending` 应变为 `false`。`discover` 列出正在配对的设备。多物理网卡时，上述命令与服务都需指定同一个 `--bind` 地址。

Windows 默认开启音量协同，网络范围为 `lan`。`enabled on|off` 控制音量协同，`scope lan|wifi` 选择局域网或双方均走 Wi-Fi；这些选项独立于麦克风授权。Windows 没有蓝牙状态传输；Mac 若仍选择 Wi-Fi 范围，Windows 走网线时会显示“等待空间条件”，需要按实际需求把 Mac 范围改为局域网。`gain 0.2` 将可控背景会话降到原音量的20%，范围0至0.5；正在录音的进程保留自己的输出。手动改动已控制会话后整轮让权，仅恢复仍匹配声邻所写值的会话；系统总音量不变。

共享麦克风需要单独授权，配对本身不会开放输入。在 Windows 运行 `sources` 取得输入 ID，`status` 取得已激活 peer ID，然后执行：

```powershell
shenglin.exe share <peerID> '<输入ID>'
shenglin.exe unshare <peerID> '<输入ID>'
```

在 Mac“设置…”→“专用麦克风”点“挂载远端麦克风…”，选择已配对 Windows、Android 或 iPad、读取已授权输入，再点“挂载”。确认已安装声邻 HAL 驱动，在录音应用的输入设置中选择新出现的“声邻 · 设备名 · 麦克风名”。挂载保存后可重启 App；已有本地专用麦克风继续共存。Mac 命令行也支持 `microphone peers`、`microphone sources <peerID>`、`microphone mount <peerID> <输入ID>`、`microphone mounts`、`microphone unmount <selector>`，通过正在运行的菜单栏 App 执行，不单独申请配对钥匙串权限。

只有应用开始使用挂载输入时，Mac 才建立认证加密连接并启动发送端采集；停止使用约一秒后释放上游。断线、共享撤销或源设备不可用时，虚拟输入归零，Mac 在仍有录音应用使用时重试新连接。重新授权或服务恢复后可自动续音。停止使用后可在设置中移除专用设备，或用 CLI 的 `unmount`。取消配对会撤销所有该关系的输入授权；单独静音挂载设备仍使用现有静音与快捷键功能。

当前音频格式为48 kHz、单声道 Float32；Windows 负责 WASAPI 共享模式转换。每个 peer 最多8条并发音频连接，同一输入向同一 peer 同时只允许一条采集流；Mac 对相同挂载复用采集。麦克风共享只开放局域网，无公网穿透。Windows CLI 不保存 PCM；Mac 的现有 HAL 诊断仍可能保存应用读到的声音，分享诊断前需检查内容。

Android 共享麦克风时，先在手机首页开启“共享内置麦克风”并允许系统录音权限，再进入“设备”→接收设备详情，开启“允许使用内置麦克风”。配对本身不会开放录音；授权保存在手机，Mac 按上面的步骤挂载“内置麦克风”。手机显示“等待接收设备使用”时没有采集，Mac 录音应用选用该虚拟输入后才开始供音。暂停自动协同不会停止共享；手机首页或常驻通知中的“停止共享”会立即断开上游。手机应用进程重启后需从前台重新开启共享。

当前 Android 只共享内置麦克风，同时供一个接收端使用。插入耳机、USB 麦克风或其他应用占用输入，可能使当前流中止；声邻不会改用另一个未授权输入。请在 Mac 查看远端错误并在手机检查输入权限或占用应用。后台首次/再次采集依赖持续存活的麦克风前台服务，厂商电池策略仍可能暂停服务；模拟器结果不能保证某款手机的锁屏表现。


iPad 首页同样提供“共享内置麦克风”，首次需允许系统麦克风权限；展开 Mac 的设备行，开启“允许使用内置麦克风”。在 Mac 挂载“内置麦克风”后，先让 iPad 声邻保持前台，再在录音应用选择该输入。供音开始后可切换应用或锁屏；完全停止使用或静音释放后，需回到 iPad 声邻前台才能再次开始。共享开关不随应用重启自动恢复，已保存的逐设备授权保留。系统中断或输入路由变化会关闭共享，并显示需要重新开启的状态。
