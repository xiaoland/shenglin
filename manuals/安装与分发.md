# 安装与分发

## Android

从 [0.2 beta.3 预发布页面](https://github.com/xiaoland/shenglin/releases/tag/v0.2.0-beta.3) 下载 `Shenglin-Android-arm.apk`。单个 APK 同时包含 `arm64-v8a` 和 `armeabi-v7a`，适用于 Android 8.0 及以上的 ARM 设备，不包含 x86 模拟器库。APK 使用独立、持久的发布密钥签名；首次从浏览器或文件管理器安装时，需允许该来源安装应用。`SHA256SUMS.txt` 用于核对下载文件。

同一发布签名后续版本可直接覆盖更新。当前实机开发版使用调试签名，不能被发布签名直接覆盖；卸载会丢失本机配对，请自行决定是否切换，安装脚本不会自动卸载或清数据。开发调试仍按[开发与诊断](开发与诊断.md)运行 `scripts/build-android.sh`，四 ABI 调试 APK 位于 `Android/app/build/outputs/apk/debug/app-debug.apk`。发布构建使用 `scripts/package-android-apk.sh`，本机签名配置与密钥留在忽略版本控制的 `local/android-release/`，不得提交或上传。维护者应安全备份该密钥及凭据；丢失后无法用相同签名继续更新。

打开声邻后开启自动协同，并在系统提示时允许通知。配对双方连接可互通的局域网（Wi-Fi 或网线），在任一端显示验证码，在另一端发现并输入；Mac、iPad 需使用 0.2 beta.3 或更新版本。无需麦克风权限；蓝牙协同需另外授予蓝牙权限并开启蓝牙，Android 11 及以下扫描还需系统定位。Android 8.0 起可安装；具体机型的录音观察、后台存续和音量控制仍以[验收记录](../docs/validation.md)为准。系统强制停止应用后需手动重新打开并开启协同。部分厂商会在省电模式下冻结前台服务；实测 HyperOS 的“省电（推荐）”设置会在锁屏后冻结声邻并中断局域网协同。此次未改变该设置，也未验证其他电池策略能否解决，不能据前台常驻通知保证锁屏可用。

## macOS

[预发布页面](https://github.com/xiaoland/shenglin/releases)提供 `Shenglin-macOS-arm64.dmg`。将其中的声邻拖入“应用程序”后启动。当前包仅由 Apple Development 证书签名，尚无 Developer ID 签名和 Apple 公证，因此 macOS 可能阻止从互联网下载的副本运行。这个 DMG 用于已了解开发版限制的测试者，不是完成公开分发签名的安装包。项目目前仅构建和验证 Apple Silicon Mac，最低系统版本为 macOS 14。

要制作可供普通用户下载后直接打开的版本，需要为 App 及内含的虚拟麦克风驱动使用 Developer ID 签名，提交 Apple 公证并把公证凭据附到发布产物。这需要发布者账户中的 Developer ID 证书及公证凭据；当前构建机只有 Apple Development 证书。准备好这些材料后，应重新打包并验证下载后的 DMG，而不是继续使用本预发布的开发签名包。

从 0.2 beta.1 起，网页协同扩展随 Mac App 打包，尚未发布到扩展商店。在“设置…”→“浏览器协同”点击“设置浏览器扩展…”会注册本机 Native Messaging 连接，并把扩展复制到 `~/Library/Application Support/Shenglin/Browser/extension`。在 Helium 的扩展管理页打开开发者模式，选择加载已解压的扩展并指定该文件夹，名称为“声邻网页协同”。更新 App 后再次运行此按钮，再由用户重新加载扩展；扩展路径保持稳定。每个通话页与背景页的参与操作见[使用指南](使用指南.md)。

## iPadOS

预发布页面也提供 `Shenglin-iPadOS-unsigned.ipa`。它不含开发签名、配置文件或测试设备标识，**不能直接点开安装**。不下载源码的测试者可使用 [AltStore Classic](https://faq.altstore.io/) 和自己的免费 Apple 账号为 IPA 签名并安装；AltStore 的[说明](https://faq.altstore.io/altstore-classic/your-altstore)指出此类应用需每 7 天续签，且免费账号有同时安装应用数量限制。此路径目前只验证了无签名 IPA 的构建、标准 `Payload/` 结构和隐私内容检查，尚未在另一台 iPad 上实测安装与运行，不能保证所有系统版本可用。自行签名后的团队身份可能与现有开发版不同，若需重装，请预期重新配对。

iPadOS 不会因为应用源码公开就允许任意设备直接安装。官方无源码分发途径是 TestFlight，或为已登记设备制作 Ad Hoc IPA；两者都需要 Apple Developer Program 的分发签名，Ad Hoc 还要求事先登记每台设备。现有真机包使用开发配置文件，仅适合已获授权的测试设备；其中的配置文件含设备标识，不应上传到公开 GitHub Release。

此外，iPad 版目前依赖私有 `AVSystemController` 属性和音量接口。将它送交 TestFlight 前，必须先处理这项分发风险并验证 App Review 是否接受；不能承诺审核通过。开发者也可在 Apple Silicon Mac 上按[开发与诊断](开发与诊断.md)构建，用自己的开发团队签名并通过 Xcode 安装。
